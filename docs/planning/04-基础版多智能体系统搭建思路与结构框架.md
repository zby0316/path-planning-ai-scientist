# 一、系统定位

## 1. 研究方向

你的研究方向可以定义为：

> 基于国产开源大模型 Qwen 的动态随机地图路径规划算法自适应选型 AI Scientist 系统研究

---

## 2. 系统要解决的问题

传统路径规划算法选型通常依赖人工经验，例如：

- 地图障碍少时用 A*；
- 环境复杂时用 ACO、PSO 或混合算法；
- 算力受限时尽量避免高耗时算法；
- 高障碍场景优先关注成功率。

但这些判断往往比较主观，难以解释和自动化。

你的系统要实现：

1. 自动识别当前地图复杂度；
2. 自动调用历史算法性能数据库；
3. 自动比较 A*、ACO、PSO、SA、混合优化算法；
4. 自动筛选最优路径规划算法；
5. 自动输出选型依据；
6. 自动生成科学假设、实验计划与验证结果；
7. 支持人在回路微调。

# 四、基础版多智能体结构框架

建议设计为 **7 个核心智能体 + 1 个总控协调器**。

---

## 1. 总控协调智能体 Orchestrator Agent

### 职责

负责调度所有子智能体，决定系统运行顺序。

### 主要任务

- 接收用户输入；
- 调用数据接收智能体；
- 调用环境分析智能体；
- 调用知识库检索智能体；
- 调用算法评估智能体；
- 调用决策智能体；
- 调用实验验证智能体；
- 调用报告生成智能体；
- 汇总最终结果。

### 作用

相当于整个 AI Scientist 系统的大脑调度中心。

---

## 2. 数据接收智能体 Data Input Agent

### 职责

接收并标准化地图环境变量。

### 输入内容

包括：

- 地图尺寸，例如 50×50、100×100；
- 障碍物占比，例如 10%、30%、60%；
- 起点和终点；
- 通道连通性；
- 是否存在动态障碍；
- 地图随机拓扑结构；
- 实时算力限制；
- 算法历史性能数据。

### 输出内容

统一格式的数据对象，例如：

```text
地图尺寸：100×100
障碍物占比：35%
动态障碍：存在
连通性：中等
算力限制：中等
场景类型：随机动态地图
```

---

## 3. 环境复杂度分析智能体 Environment Analysis Agent

### 职责

根据地图特征判断环境复杂度。

### 基础规则

按照你之前定义的规则：

```text
障碍物占比 < 20%：低复杂度
20% ≤ 障碍物占比 ≤ 50%：中复杂度
障碍物占比 > 50%：高复杂度
```

### 可扩展因素

除了障碍物占比，还可以逐步加入：

- 地图尺寸；
- 起点终点距离；
- 可通行区域比例；
- 连通区域数量；
- 动态障碍变化频率；
- 路径弯折程度；
- 死胡同数量；
- 通道宽度；
- 算力预算。

### 输出内容

例如：

```text
当前场景等级：中复杂度
原因：障碍物占比为 35%，处于 20%~50% 区间；地图存在动态障碍，连通性中等。
```

---

## 4. 算法知识库智能体 Algorithm Knowledge Agent

### 职责

管理五种路径规划算法的知识和历史性能数据。

### 可选算法集合

严格限制在以下 5 种：

1. A*
2. 蚁群算法 ACO
3. 粒子群算法 PSO
4. 模拟退火算法 SA
5. 混合优化算法

### 知识库内容

每种算法需要记录：

- 适用场景；
- 不适用场景；
- 平均耗时；
- 平均路径长度；
- 寻路成功率；
- 收敛稳定性；
- 是否适合动态地图；
- 是否适合高障碍环境；
- 是否适合算力受限环境。

### 示例知识库字段

```text
算法名称
适用复杂度
平均耗时
平均路径长度
成功率
优点
缺点
适配边界
历史实验来源
```

### 注意

比赛要求强调“依据真实数据和知识库”，所以不能凭空写结论。基础版可以先用你自己仿真实验得到的结果作为知识库数据。

---

## 5. 算法评估智能体 Algorithm Evaluation Agent

### 职责

对五种算法进行量化评分。

### 核心评价指标

建议包括：

1. 运行耗时；
2. 路径长度；
3. 寻路成功率；
4. 稳定性；
5. 动态环境适应能力；
6. 算力消耗。

### 基础评分思想

不同场景下权重不同：

#### 低复杂度地图

优先考虑速度：

```text
耗时权重高
路径长度权重中等
成功率权重中等
```

#### 中复杂度地图

综合考虑：

```text
耗时、路径长度、成功率均衡
```

#### 高复杂度地图

优先考虑成功率：

```text
成功率权重最高
路径质量次之
耗时权重降低
```

#### 算力受限场景

优先考虑运行耗时：

```text
耗时权重最高
复杂算法需要降权
```

---

## 6. 推理决策智能体 Decision Reasoning Agent

### 职责

根据环境分析和算法评估结果，输出最优算法。

### 需要遵守的硬性规则

你之前给出的规则可以直接作为系统约束：

1. 只能从 A*、ACO、PSO、SA、混合优化算法中选择；
2. 决策必须依托实测动态数据和算法知识库；
3. 每次地图重启后必须重新计算；
4. 算力受限时优先考虑耗时；
5. 高障碍复杂环境优先考虑成功率。

### 输出格式

需要满足你之前设定的格式：

```text
当前场景等级：中复杂度
选定最优算法名称：混合优化算法
简短选型依据：当前障碍物占比为 35%，属于中复杂度场景。根据历史性能数据库，混合优化算法在该复杂度下成功率较高、路径长度较短，虽然耗时略高，但在当前算力限制下仍可接受。
```

---

## 7. 实验验证智能体 Experiment Agent

### 职责

验证系统推荐的算法是否真的合理。

### 实验任务

它可以自动执行或组织以下实验：

- 生成随机地图；
- 控制障碍物比例；
- 分别运行五种算法；
- 记录耗时；
- 记录路径长度；
- 记录是否成功找到路径；
- 对比推荐算法与其他算法；
- 更新算法性能数据库。

### 评估指标

建议使用：

1. 平均运行时间；
2. 平均路径长度；
3. 成功率；
4. 收敛次数；
5. 路径平滑度；
6. 算法稳定性；
7. 综合评分。

### 作用

这是让系统符合比赛“可验证科学假设”的关键模块。

## 8. 科学假设生成智能体 Hypothesis Generation Agent

### 职责

把算法选型结果上升为“科学假设”。

### 示例假设

```text

```

### 输出内容应包括

根据 PDF 要求，可以生成：

1. 待研究问题；
2. 解决思路；
3. 技术手段；
4. 数据集；

8. 摘要；

11. 实验结果；
12. 参考文献。

## 2. 各部分推荐语言

| 模块 | 推荐语言/技术 |
|---|---|
| 路径规划算法 | Python |
| 多智能体调度 | Python |

| 可视化 | Python |

| 报告生成 | Markdown / PDF |
| 实验图表 | Matplotlib / Plotly |

---

## 3. GUI 用 Python 还是 Rust？

基础版建议用 **Python**。

原因：

1. 开发速度快；
2. 和路径规划算法、数据分析模块兼容性好；
3. Streamlit 可以快速做演示界面；
4. PySide6 可以做更正式的桌面 GUI；
5. 比赛更看重系统逻辑、实验验证和 AI Scientist 能力，不一定需要复杂前端。

Rust 更适合性能要求很高、需要底层优化的场景。对于比赛基础版来说，Rust 会增加开发难度，不建议作为主语言。

如果后期想提升性能，可以考虑：

```text
Python 负责系统调度和 GUI
Rust/C++ 负责高性能路径规划算法内核
```

但基础版没有必要。

# 十一、技术难点

基础版系统的主要难点有以下几个。

## 1. 动态地图复杂度量化

不能只看障碍物占比，还需要逐步考虑：

- 地图连通性；
- 死路数量；
- 通道宽度；
- 动态障碍变化频率；
- 起点终点可达性。

---

## 2. 五种算法公平对比

不同算法参数差异较大，需要统一实验条件，例如：

- 同一地图；
- 同一起点终点；
- 同一运行次数；
- 同一硬件环境；
- 同一评价指标。

---

## 3. 知识库数据真实性

比赛强调不能虚构参考文献和实验依据。

所以你需要：

- 保存真实实验结果；
- 记录实验参数；
- 记录运行时间；
- 记录失败案例；
- 形成可复现实验日志。

---

## 4. 大模型不能替代算法执行

Qwen 适合做：

- 推理解释；
- 研究假设生成；
- 报告撰写；
- 智能体对话。

但路径规划和实验指标必须由实际代码运行得到。

---

## 5. 多智能体之间的信息一致性

不同智能体之间必须共享同一份数据状态，避免出现：

- 环境智能体判断为中复杂度；
- 决策智能体却按高复杂度处理；
- 报告智能体生成了不一致结论。

建议用统一的任务状态对象保存全流程数据。

---
