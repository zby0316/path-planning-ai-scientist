# 路径规划虚拟仿真闭环 AI Scientist 系统改造交付说明

## 一、改造目标

本次改造将原 `ai_scientist_path_planning` 项目重命名并升级为：

`路径规划虚拟仿真闭环AI科学家系统`

改造目标是让系统从“路径规划算法自适应选型/推荐”进一步贴合赛题论证方案中的定位：

- 以动态栅格地图作为虚拟仿真实验仪器。
- 面向救援机器人/无人机路径规划场景。
- 对 A*、ACO、PSO、SA、混合优化算法进行可复现实验比较。
- 研究算法在障碍物占比、连通性、拓扑随机性、动态变化率和算力限制下的适配边界。
- 形成“假设生成 -> 仿真实验 -> 结果分析 -> 反思反馈 -> 下一轮实验计划”的 AI Scientist 闭环。

## 二、已完成内容

### 1. 项目文件夹中文重命名

原文件夹：

`ai_scientist_path_planning`

已重命名为：

`路径规划虚拟仿真闭环AI科学家系统`

源码中未发现硬编码旧英文目录名，重命名主要影响运行时进入目录的路径。

### 2. 动态栅格地图生成

修改文件：

- `map/map_generator.py`

新增能力：

- `perturb_dynamic_obstacles()`：基于上一帧地图扰动动态障碍物。
- `generate_dynamic_sequence()`：生成多时间片动态栅格地图序列。

保留行为：

- 原有 `generate()` 静态地图生成方法保持不变。
- 起点和终点在动态扰动中始终保持可通行。
- `dynamic_change_rate=0` 时动态序列保持静态不变。

### 3. 动态仿真实验运行

修改文件：

- `evaluation/benchmark.py`
- `evaluation/experiment_runner.py`
- `agents/experiment_agent.py`

新增能力：

- `BenchmarkRunner.run_dynamic_sequence()` 支持对动态地图序列逐帧重规划。
- 实验结果新增 `dynamic_steps` 和 `dynamic_failure_frames`。
- `ExperimentAgent` 会读取 `dynamic_change_rate`，并在动态场景下写入 `dynamic_random` 类型地图。
- `ExperimentRunner.run_quick()` 和 `ExperimentRunner.run_matrix()` 支持动态变化率参数，默认仍为静态实验。

兼容性：

- 未传入 `dynamic_change_rate` 时，旧实验流程不受影响。
- 静态 benchmark 与原测试用例保持兼容。

### 4. API 动态参数适配

修改文件：

- `api/schemas.py`
- `api/server.py`

新增能力：

- `/analyze` 请求模型新增 `dynamic_change_rate`。
- `/experiment` 请求模型新增 `dynamic_change_rate`。
- API 实验接口会把动态变化率和动态时间片传递给 `ExperimentRunner`。
- API 报告接口可以处理列表型实验结果，并自动推断当前最优算法。

### 5. 研究报告赛题表达增强

修改文件：

- `reports/report_generator.py`

新增内容：

- 数据集章节体现动态变化率。

- 实验结果章节体现动态失败帧。
- 方法论章节明确写入“动态栅格地图虚拟实验仪器”和“反馈迭代机制”。

这使报告更符合“虚拟仿真闭环 AI Scientist 系统”的参赛叙事。

## 五、参赛适配亮点

本次改造后，项目具备更清晰的赛题适配表达：

1. **虚拟仿真实验仪器明确化**  
   动态栅格地图不再只是输入参数，而是可以生成时间序列并驱动逐帧重规划实验。

2. **科学问题从推荐最优算法升级为发现适配边界**  
   系统可以围绕障碍物占比、连通性、拓扑随机性、动态变化率、算力限制观察算法表现变化。

3. **AI Scientist 闭环更完整**  
   已有 `ScientificDiscoveryPipeline`、`HypothesisAgent`、`ExperimentAgent`、`ReflectionAgent` 可以和动态仿真实验结果衔接。

4. **报告输出支撑答辩叙事**  
   研究报告会显式呈现动态仿真、适配边界和反馈迭代，而不是只展示算法推荐结论。

5. **Qwen 定位更一致**  
   客户端和配置已改为优先 Qwen，DeepSeek 仅作为兼容回退，更符合技术边界声明。
