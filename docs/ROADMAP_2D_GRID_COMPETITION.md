# 2D 栅格地图比赛版建设路线图

## 目标验收口径

一次比赛演示应能从真实/合成 2D 栅格地图开始，完整产出：数据卡、环境特征、
五算法可复现实验、数据驱动排名、参数推荐、文献证据、可证伪假设、验证结果、
反思与人工复核记录，以及可下载的最终报告。

## P0：工程基线与安全

- 修复所有路径，使 CLI、GUI、API 从任意工作目录启动均一致。
- 统一配置、日志、错误模型和随机种子。
- 建立 Git、忽略规则、README、依赖锁定和一键验证命令。
- 把真实密钥移出可提交内容；若曾外泄则轮换。

验收：测试通过；父目录与主线目录启动结果一致；Git 不显示密钥和虚拟环境。

## P1：2D 数据闭环

- 将 `assets/maps/` 中的 MovingAI 地图登记到统一数据目录或数据清单，不复制无必要的大文件。
- 同时支持 `.map`、`.scen`、CSV 和参数生成地图。
- 为每张地图保存来源、哈希、尺寸、障碍率、连通性、起终点和场景标签。
- 划分训练/开发/最终展示集合，避免用展示地图反复调参。

验收：选定地图可一键载入、校验、复现实验；错误地图给出清晰原因。

## P2：可信实验与算法选型

- 五算法统一接口、超时、随机种子、重复次数和失败语义。
- 保存每一次原始运行，禁止只保存均值。
- 指标至少覆盖成功率、路径长度、运行时间、稳定性和动态重规划表现。
- 避免评分饱和；归一化参数只从预先定义的基准集产生。
- 增加消融、置信区间、失败案例回放和选择后再验证。

验收：同一配置可复现；排名能追溯到原始运行；不存在大量无解释的满分指标。

## P3：受控文献与科学假设

- 用 `tools/import_literature.py` 生成候选，不自动进入可信知识库。
- 人工复核标题、作者、年份、DOI、算法、实验对象和证据原文。
- 文献事实与系统实验事实分开存储，并记录来源定位。
- 假设必须含变量、对照、阈值、否证条件和实验计划。

验收：报告中的每条外部结论都可定位到文献；每条系统结论都可定位到实验记录。

## P4：统一闭环服务

- 以 `ScientificDiscoveryPipeline` 或新的应用服务作为唯一业务入口。
- CLI、Streamlit、FastAPI 只负责输入输出，不复制选型逻辑。
- 明确智能体失败策略：关键实验失败应阻止结论，非关键解释失败可降级。
- 保存 ResearchState 状态迁移、人工意见和最终决策版本。

验收：三种入口对相同输入返回同一核心结果；失败不会被静默吞掉。

## P5：比赛演示与交付

- 固化 3～5 个代表场景：低/中/高复杂度、窄通道、动态障碍。
- GUI 展示“输入—证据—实验—决策—假设—反思—人工确认”的因果链。
- 优化 Streamlit 弃用 API、计算缓存和长实验进度反馈。
- 一键导出 Markdown/PDF、实验 CSV/JSON、配置和引用。
- 准备离线降级：无 Qwen 时实验与选型仍可运行，解释明确标注降级。

验收：全流程演示稳定、限时内完成、可离线复核、报告无不可追溯结论。

## 暂缓范围

- 3D 体素地图、机械臂、真实车辆控制。
- 多机器人协同规划和任务分配。
- SLAM 全栈、强化学习训练平台、大规模分布式部署。
- 超出白名单的新算法；可保留研究记录，但不进入近期比赛主链。
